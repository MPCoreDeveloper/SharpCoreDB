## Thanks

| Contributor | Contribution |
|---|---|
| [@CastleSoft](https://github.com/CastleSoft) | Reported [issue #497](https://github.com/MPCoreDeveloper/SharpCoreDB/issues/497): `SharpCoreDB.Functional.Linq2DB` 2.1.2 opened Microsoft.Data.Sqlite and the native `e_sqlite3` library instead of a SharpCoreDB database, so a password was refused and rows landed in an unencrypted `SQLite format 3` file. The report came with a minimal reproduction, the exact package versions and the failing exception text, which is what made the adapter fix possible in one pass — and the same reproduction then exposed two DDL defects the suite had missed: a quoted identifier in `CREATE TABLE` was catalogued with its quoting, so a schema generated by a query builder could create its table and then not insert into it. Fixed in `2.1.3` (adapter) and on `master` (quoted DDL — `tests/SharpCoreDB.Tests/QuotedIdentifierDdlTests.cs`); recorded in `docs/CHANGELOG.md`. |

## How to appear here

A report is a contribution when it can be acted on: the version you ran, the smallest snippet that reproduces the
behaviour, the exception text, and what you expected instead. Those reports are what turn "something is wrong" into a
red test and a fix — see [docs/CONTRIBUTING.md](docs/CONTRIBUTING.md).
